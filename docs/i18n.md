# Current-site languages

The current site supports English at its existing URLs and Latin American Spanish
under `/es/`. The preserved sites in `apps/v1` through `apps/v4`, their URLs and
content remain unchanged. Image and PDF downloads, manifests, the English feeds and the
English search-index endpoint retain their original paths. `/es/feed.xml` and `/es/feed.json`
list only articles with a complete translation, at their Spanish addresses, and Spanish pages
advertise them in `<head>`; visible feed links still point to the English feeds. English is the primary language,
the default locale, and the fallback when a Spanish message is missing or blank.
Browser language and previous visits do not redirect unprefixed URLs to Spanish.

Spanish route files reuse the current-site page components and published English
entry list. Each article or case study can supply an adjacent `index.es.md` or
`index.es.mdx` with its complete Spanish body and translated copy. The dedicated
`postTranslation` and `projectTranslation` collections validate those files with
strict schemas. Original entries retain publication dates, scheduling, draft
status, taxonomy, asset paths, project destinations, and content identity.
Translations cannot override those fields or publish an otherwise hidden entry.

Translated pages use their own Spanish canonical URL, Spanish structured-data
language, and localized social card. Original and translated pages advertise
reciprocal `en`/`es` alternates and enter the sitemap. An English article syndicated
elsewhere retains its external canonical and attribution; its Spanish translation
has a local canonical and is indexable, but the pair omits language alternates
because the external original cannot supply a reciprocal link.

A missing translation falls back to the English body with `lang="en"`, the English
article notice, no language alternates, and `noindex, follow` on its Spanish route.
The sitemap continues to exclude these fallbacks. Translate the complete body and
metadata before enabling a new pair; do not remove the fallback safeguard.
Giscus discussions and Webmention reactions keep the canonical English content
identity. Heading IDs remain identical across languages while outline labels are
translated, preserving section links and language-switch fragments. Translators
must retain the original heading hierarchy and code samples.

Messages live in `src/i18n/catalogs/`, grouped into page, collection, article,
and shared controls. Each stable key owns its English source and Spanish translation.

Blog archive introductions use `catalogs/topic-notes.ts`, keyed by the authored
tag identifier. `getBlogTopicNote(tag, locale)` uses the same typed translator and
English fallback. Keep each note grounded in the topic's published articles and
update both languages when its coverage changes. The visible note and page metadata
share this source; new tags without a note use the collection's localized generic
description until one is authored. Topic names retain their authored identifiers.

Use `pageTranslator(locale)`, `collectionTranslator(locale)`,
`articleTranslator(locale)`, or `sharedTranslator(locale)` for UI copy. Omitting
the locale selects English. Keep the key unchanged when editing wording:

```ts
const t = sharedTranslator(locale)
const aboutLabel = t('nav.about')
```

Keys and required interpolation fields are checked by TypeScript. Catalogs must
satisfy `MessageCatalog`, which requires both languages; unit checks reject empty
messages and mismatched placeholders, and keep source-text lookups unambiguous. This catches omissions during development
while the runtime retains its English fallback. Shared messages are referenced
from other catalogs when the wording and translation are identical.

Client controllers pass a locale callback, such as
`sharedTranslator(() => getLocale(window.location.pathname))`, so an existing
controller reads the new language after Astro navigation. Only the shared control
catalog is included by these controllers. Profile and contact data use locale-aware
factories with keyed messages; their existing exports retain English defaults.

The explicit `localizePageSource`, `localizeCollectionSource`, and
`localizeArticleSource` adapters handle authored content, generated controls, and
metadata that arrive as text. They preserve unknown English content. Do not use
them for new UI literals: add a stable key and use a typed translator instead.

Generated article copy controls localize visible labels and accessible names
together. Their HTML matcher preserves quoted command attributes containing angle
brackets; localization must leave the copied command byte for byte unchanged.

Metadata and OG cards use the authored translation and the normal generation
command. Topic and technology archives with fewer than three entries remain
non-indexable in either language and share their index card.

Article and case-study prose, headings, frontmatter descriptions, image alt text,
captions, and visible MDX props are translated into Latin American Spanish.
Product and organization names, code samples, and quoted recommendations retain
their original wording when appropriate. Five title-only travel drafts have no
body to translate and remain unpublished. Authored future posts have translations
but retain the original publication schedule.

The shared language switch preserves the page, query, and fragment. The header
label describes the destination interface and the menu uses its complete label.
Article hero Series bylines use the same typed position message as the closing
navigation and localize their overview destination. Series names retain their
authored English wording and language marker inside either interface.
New translations must not flip draft flags or create independent content copies.
Spanish résumé downloads use the existing English PDFs and identify that language.

Run `pnpm run lint`, `pnpm run check`, the locale unit tests and
`tests/i18n.spec.ts`, then the normal release verification gate. Rendered checks
cover mobile and desktop language navigation, search labels, route metadata and
translated prose, stable section links, and fallback behavior. Spanish spelling uses the maintained CSpell
Spanish dictionary in the root configuration.

Full-text search loads Pagefind only when the primary index leaves room for body
matches. It searches the published article and case-study corpus in the active document
language. `/search-index.json` and `/es/search-index.json` contain localized primary
results; client navigation reloads that index and reinitializes Pagefind when the
language changes. Timeouts and unavailable fragments
preserve primary matches and expose a useful failure message when no matches can
be verified. Pagefind assets bypass the service-worker cache. Offline navigation
under `/es/` uses the cached Spanish offline page.
