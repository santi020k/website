# Current-site languages

The current site supports English at its existing URLs and Latin American Spanish
under `/es/`. The preserved sites in `apps/v1` through `apps/v4`, their URLs and
content remain unchanged. Feeds, image and PDF downloads, manifests and the
search-index endpoint retain their original paths.

Spanish route files are thin wrappers around the same current-site page
components. Dynamic wrappers reuse `getStaticPaths` and the original component
props, so published entries, ordering, draft filtering and pagination have one
source of truth. The HTML language, canonical URL and alternate language links
reflect the route. Entries with an external canonical URL retain it, omit internal language alternates and stay outside the sitemap in both locales. Existing Giscus discussions and Webmention reactions share the canonical English content identity. Shared locale helpers preserve query strings and fragments;
the language switcher preserves the current page and query.

Page copy belongs in `src/i18n/page-copy.ts`; collection shell copy belongs in
`src/i18n/collection-copy.ts`; shared controls and client messages use
`src/i18n/shared-copy.ts`. Keep both languages aligned when changing visible copy.
Only the shared UI dictionary is included by client controllers. Metadata and OG
cards use the same translation sources and the normal generation command. Non-indexable pages reuse their existing default card when no localized route card is generated.

Published blog posts and case-study bodies retain their authored English prose,
marked with `lang="en"` inside the Spanish shell. Product and organization names,
code samples and quoted recommendations also retain their original wording.
New translations must not flip draft flags or create independent content copies.
Spanish résumé downloads use the existing English PDFs and identify that language.

Run `pnpm run lint`, `pnpm run check`, the locale unit tests and
`tests/i18n.spec.ts`, then the normal release verification gate. Rendered checks
cover mobile and desktop language navigation, search labels, route metadata and
English prose within Spanish shells. Spanish spelling uses the maintained CSpell
Spanish dictionary in the root configuration.

Full-text search loads Pagefind only when the primary index leaves room for body
matches. It searches the published English article and case-study corpus, then
links results into the active language shell. Timeouts and unavailable fragments
preserve primary matches and expose a useful failure message when no matches can
be verified. Pagefind assets bypass the service-worker cache. Offline navigation
under `/es/` uses the cached Spanish offline page.
