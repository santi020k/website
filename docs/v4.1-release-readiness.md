# Website v4.1.0 release readiness

This record covers local preparation of `release/v4.1.0` on October 21, 2026.
The production base is `2e8171e9`, the released v4.0.0 commit. Preparation started
from integrated candidate `59932d16`; runtime and asset review commit `72f5746a`
is included in this candidate. No push, pull request, remote merge, tag,
GitHub Release, or deployment is authorized by this preparation.

## Scope and versioning

The release adds the website history timeline and maintained v1, v2, and v3
archives, a private history-film studio, refreshed project discovery and product
previews, and the Timeline career layout. It also improves reading, search,
keyboard navigation, enlarged-text layouts, asset delivery, metadata, and offline
cache behavior. `CHANGELOG.md` contains the generated release notes.

`pnpm run version-packages` consumes the pending Changesets and sets the root
website package to 4.1.0. Historical apps keep their original version labels and
remain excluded from release versioning. The existing lockfile and dependency
versions are retained. Both resume PDFs were regenerated because their source
fingerprint includes the root manifest and shared render dependencies. All five
pages match the preserved release PDFs in extracted text and rendered pixels.

The preserved `fix/reveal-threshold-cleanup` checkpoint is intentionally excluded.
Its shared-runtime proposal changed custom reveal timing and was rejected; the
current site retains explicit viewport-entry thresholds and their regressions.
See [Tall reveal groups](lumen-integration.md#tall-reveal-groups).

## Local qualification

Validation uses Node 24.21.0 and the pinned pnpm 11.25.0. The pending preparation
was preserved in commit `d43e57b6` before merging the reviewed runtime and asset
changes. An existing preview and other checkouts are retained. Browser checks
use a separate preview port with Astro's `--ignore-lock` option; the test matrix
and assertions are unchanged, and qualification disables retries.

The frozen install and full dependency audit pass with no known vulnerabilities.
The production build, zero-warning workspace lint and Astro checks, spelling,
Markdown and content checks, CV freshness, all 502 unit tests, and all seven motion
tests pass. Coverage is 94.94% statements, 89.95% branches, 97.54% functions, and
95.88% lines, above every configured threshold. SEO validation reports no errors
or warnings; archive checks cover 841 pages and the built-page audit covers 1,291
documents and 5,116 local targets with no errors. OG generation reuses all 473
images without regeneration.

The last reading-layout failure came from a deferred header-padding transition
after client navigation and root text resizing. The reduced-motion header now
applies its geometry immediately. All 120 repeated reading-navigation checks
pass without retries, including both themes, phone and desktop widths, and
125–200% text. Normal-layout screenshots are preserved at 390px and 1440px;
enlarged-text comparisons cover both themes. The full 1,543-test Chromium suite,
focused WebKit checks, and three-run Lighthouse qualification are still pending.

The optional Workspace Organizer sitemap was unavailable during generation and
was excluded as designed. The combined sitemap contains 1,353 URLs. This does not
establish the availability of that separate product's deployment.

Temporary logs and browser diagnostics are stored in `.cache/release-v4.1.0-final/`.
They are local evidence and are not committed release artifacts.

## Publication and recovery

After separate authorization, push this prepared release branch and open its
pull request into `main`. Require the current GitHub checks and resolve all
review findings before merging. Because this branch already contains the version
bump and matching changelog, the existing Release workflow creates `v4.1.0` and
the GitHub Release from the merged `main` commit; a second version bump is not
needed. Cloudflare Pages deploys that reviewed commit through the existing flow.

Verify the deployed revision, then smoke-check the routes in the
[deployment runbook](deployment.md#release-flow), plus `/history/`, `/v1/`, `/v2/`,
`/v3/`, retired-content redirects, search, theme persistence, and both resume
downloads. Confirm archives remain excluded from indexing and their navigation
stays within the selected era. Local checks do not establish production results.

No data migration is required. If production verification fails, promote the
previous healthy Cloudflare deployment or revert the release through a reviewed
pull request, then repeat the smoke checks. Preserve published tags and archive
source snapshots; never move a published tag to repair a release.
